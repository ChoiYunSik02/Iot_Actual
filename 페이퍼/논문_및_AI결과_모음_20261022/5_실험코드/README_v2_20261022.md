# 2026-10-22 점검 — 원문식 모델(cos_twice)과 평가 수정판

## 왜 만들었나
기존 결과(`README.md`)는 `rstlcd.py` 기본값(강성 = m·ω², cosθ 한 번)으로 계산했다. 원문 PDF 9쪽 식 (16)(17)(20)은
m_dx = m_d·cosθ, k_dx = 2·m_dx·g/(H_vL+H_vR+λB)·cosθ 라서 **강성에 cosθ가 한 번 더** 들어간다(`cos_twice=True`).

## 점검 결과 (PEER 8쌍, 6지표 평균 저감률 %, ×30 감쇠 보정, 같은 입력)
| 모델 | 수동 | S-TLCD | RS(원문 웨이블릿) | RS − 수동 |
|---|---|---|---|---|
| 기존 기본값 (cos 한 번) | 15.56 | 15.43 | 15.31 | −0.25 |
| **원문식 (cos_twice)** | 15.56 | 15.43 | **16.12** | **+0.56** |
| 질량 보존형 (cos²) | 15.56 | 15.43 | 12.89 | −2.68 |
(원문 표 7, 15쌍: 수동 16.00, RS 18.80 — 여전히 +2.7%p 모자람)

## Oracle 여지 (실제 11쌍, 격자 7×7 = 0.3204~0.3542 Hz × 0~90°, 고정 f·θ, 건물 k=1)
| 모델 | 최선 고정값 | Oracle | 여지 | f만 자유 | θ만 자유 |
|---|---|---|---|---|---|
| 기존 | 15.89 (0.3204 Hz, 30°) | 16.49 | 0.59 | 0.09 | 0.33 |
| **원문식** | 15.83 (0.3542 Hz, 45°) | 17.60 | **1.77** | 0.73 | 0.81 |
- 원문식에서는 θ가 진동수를 √cosθ배로 옮기므로 f와 θ가 얽힌다 → 최선 고정 f가 범위 상단.
- 기록별 손해(Oracle − 최선 고정): 포항 7.36, El Centro Array #11 2.46, KJMA 2.05, El Centro 1940 2.11 …
- 주의: 최선 고정값은 11쌍에서 사후 선택(고정값에 유리한 기준). 원문 PDF와 재현 격차(2.7%p)가 남아 있어 절대 수치는 잠정.

## 새 파일 (기존 파일은 그대로)
- `rstlcd_cos2.py` : `simulate`의 `cos_twice` 기본값을 True로 바꾼 래퍼
- `gen_labels_v2.py` : 같은 라벨 생성기, 결과 폴더 `data/labels_cos2/` (태그 `_cos2`)
- `train_ai_v2.py` : 평가 수정판
  - 지진(사건) 단위 분리: Imperial Valley 1979 기록(PEER 1·2·3·4·11)은 한 묶음으로 같이 제외
  - 고정값 기준선을 **학습 분할 안에서** 선택 (시험 기록 변형 제외)
  - 학습 시드 `--seeds`개 반복 → 평균 ± 표준편차, AI − 고정값도 ± 표준편차로 보고
  - 한국 기록(포항·경주)만 따로 AI − 고정값 출력
- 점검 스크립트는 세션 임시 폴더라 저장하지 않음. 필요하면 위 표의 조건으로 다시 만들 수 있음.

## 실행 (Ryzen 9 7945HX 16코어/32스레드 · RTX 4070 Laptop · RAM 32GB)
```
cd 페이퍼/코드
python gen_labels_v2.py --n 2000 --workers 16          # (물리 코어 수. 약 2~3시간 예상, 실측 필요) 중간에 끊겨도 이어서. data/labels_cos2/ (샘플 6개는 이미 있음)
python train_ai_v2.py --tobs 1 3 5 --kscale 1.0 0.9025 1.1025 --seeds 5
# Windows는 실행 전에 set OMP_NUM_THREADS=1 (워커마다 BLAS 스레드가 겹치지 않게), 노트북은 전원 연결 + 고성능 모드
# ±20% : TLCD_FRANGE=0.2 TLCD_NF=13 로 두 명령 모두 (data/labels_r20_cos2/)
```
- 검증한 것: 라벨 생성(6개), 평가 로직(torch를 numpy 회귀로 바꾼 모의 실행). **torch 학습 자체는 이 환경에 torch가 없어 실행하지 못함.**

| 건물 | E1b 수동 디튜닝 | E2 원문 RS | 고정값 | Oracle(고정 상한) | Oracle − 고정 |
|---|---|---|---|---|---|
| k=1 (0.3373 Hz) | 13.36 | 14.04 | 15.81 | 17.60 | 1.80 |
| k=0.9025 | 15.93 | 16.17 | 18.34 | 21.65 | 3.31 |
| k=1.1025 | 13.32 | 13.25 | 14.78 | 15.99 | 1.22 |
- AI − 고정값 (9조건: T_obs 1·3·5 s × 건물 3가지): preset 기록단위 평균 −0.18%p(사건단위 +0.11), online −0.17%p(사건단위 −0.64). 일관되게 이기는 조건 없음.
- 시드 표준편차(0.1~0.7%p)는 새 지진에서의 불확실성이 아님. 사건단위(7개) SE는 0.12~1.30%p.
- "Oracle 여지 회수 33~56%"는 고정값만으로도 얻는 몫(고정 − E2 = 1.5~2.2%p, Oracle − E2의 39~56%)과 같아서 AI의 몫이 아님.
- 포항·경주만: k=0.9025에서 AI − 고정 +1.3~2.0%p (기록 2개, 시드 편차 0.5~0.7). 포항은 Oracle − 고정 8.05%p로 여지가 가장 큼.
- online이 "고정 상한" Oracle을 넘는 기록 있음 (PEER 3: +4.8~9.6%p, PEER 2: +1.7~3.0%p) → 대기 후 전환 같은 시간 가변 전략은 격자 Oracle이 상한이 아님. 진단: `exp_switch.py`.

## 시간 가변 전략 진단 (`exp_switch.py`, 실제 11쌍, 건물 k=1, 결과 `results/exp_switch_cos2.json`)
평소값(0.3373 Hz, 0°)으로 대기하다 트리거(0.5 gal) + d초에 (f, θ)로 한 번 전환. 6지표 평균 저감률 [%]:
| d | pre(처음부터 고정) | 0 | 1 | 2 | 3 | 5 | 8 |
|---|---|---|---|---|---|---|---|
| 최선 고정칸 평균 | 15.83 | 15.84 | 15.81 | 15.66 | 15.50 | 15.37 | **17.18** |
| 기록별 Oracle 평균 | 17.60 | 17.60 | 17.53 | 17.58 | 17.39 | 17.60 | 18.44 |
- 기록별 (칸, d) 전체 Oracle 19.48 → 시간 가변 여지(사후 상한) 3.65%p. 시험한 d의 끝값(8)이 최선인 기록이 6개 → 더 늦은 d를 아직 안 봄.
- 같은 칸(f6, 45°)에서 pre → d=8: PEER 3 +9.19, PEER 2 +5.82, Pacoima +2.83, Brawley +1.68 / KJMA −5.96, 경주 −1.76. 기록 편차가 매우 큼.
- **같은 지진을 뺀 교차검증:** d=8 한 가지(칸은 학습 사건에서 선택) 기록단위 pre 대비 +2.07%p지만 사건단위(7개) +0.16 ± 1.45%p (4/7 개선). 전체 후보(pre + d 0~8)에서 고르면 −0.61 ± 1.16%p. → 일반화된 이득으로는 확인되지 않음.
- 기록 11개 중 5개가 Imperial Valley 1979 한 사건. 이득은 주로 이 사건의 일부 관측소(PEER 3 +9.2, PEER 2 +5.8, PEER 4 +1.7)와 Pacoima(+2.8)에서 나옴. 이 사건을 빼면 pre 선택도 무너짐(PEER 3 12.01).
- 강진동 시점이 트리거 기준 2~25 s로 제각각이라 "트리거 + d초" 타이머는 기준으로 부적절. 전환 기준을 응답 기반(에너지 누적 등)으로 정의해야 비교 가능.
