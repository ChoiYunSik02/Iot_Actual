# 개발 설정 변경 기록 (config/experiment.json)

`gate('require', …)`는 A~C 관문을 통과한 뒤 `experiment.json`이 바뀌었으면, 새 설정 해시(`run_provenance().config_hash`, 16자리)가 이 파일에 적혀 있는지 확인합니다. 적혀 있지 않으면 D 이후 단계를 시작하지 않습니다.
설정을 바꾸면 아래 형식으로 항목을 추가하고, A·B·SL·C 관문과 D 진단을 다시 돌린 뒤 F(AI 비교) 전에 `config/frozen/`으로 다시 고정합니다.
시험 기준·자료·평가지표·허용 악화폭은 이 경로로 바꾸지 않습니다(계획서 0절).

```
## <날짜> <이전 해시> → <새 해시>
- 바꾼 항목: (예) controller.C1.dtheta_deg [-15 0 15] → [-30 0 30]
- 이유: (D 진단 근거 파일과 수치)
- 이전 결과: results/… (S, ΔS, 비틀림 악화 사건 수)
- 이후 결과: results/… (같은 표)
- 결정: 유지 / 되돌림
```

## 2026-10-28 (클라우드, 노트북 실행 전) 초기 설정
- `latency.deadline_action` 대신 `latency.timing_mode`('actual'/'nominal')와 시험용 `inject_*`를 넣었습니다. 실측 계산시간을 시간축에 반영하라는 요청 때문입니다.
- 노트북 관문이 아직 없으므로 이 변경은 관문 비교 대상이 아닙니다. 첫 관문 기록이 기준 해시가 됩니다.

## 2026-10-28 (노트북 첫 실행 A 실패 후, 관문 통과 전) 계산 예산 기본값
- 노트북 A 단계 실패 원인: `verify_scales`가 `timing_mode=actual`과 계산 예산 0으로 R을 돌렸습니다. 그래서 모든 R 지령이 '늦음'으로 처리돼 적용되지 않았고, `scales.json`(nominal 정의)과 11.6 % 달랐습니다.
- 수정 내용:
  - `scales` 계산과 검증은 nominal로 고정했습니다.
  - `latency.compute_s` 기본값을 0.0에서 null(미측정)로 바꿨습니다.
  - actual 시간축에서 미측정 예산이 있으면 실행을 거부하게 했습니다.
- 이 변경은 첫 MATLAB 관문 통과 전이라 관문 비교 대상이 아닙니다.

## 2026-10-28 18:40 (노트북 첫 D 실행 후) 계산 예산 적용 버그 수정 — 설정 변경 아님

- 원인: `pc_method`의 `[M.select_s, M] = getc(...)`는 두 번째 출력(M)이 첫 번째 대입을 덮어씁니다. 그래서 모든 방식의 계산 예산이 0이었습니다.
  - 그 결과 d_cmd가 0이 되어 모든 펌프·각도 지령이 '늦음 → 보류'로 처리됐고, 장치는 밸브만 움직였습니다.
- 영향:
  - 노트북 첫 D_main·D_ofat 결과는 무효입니다.
  - D_nominal0, A·B·SL·C 관문은 nominal·명시적 예산을 써서 영향이 없습니다.
- 수정: `getc`가 M에 직접 값을 넣도록 바꿨습니다. C 단계에 T9(실측 예산 → d_cmd, d_fc 반영)를 추가했습니다.
- `experiment.json`은 바꾸지 않았습니다(설정 해시 동일). 코드 digest가 바뀌므로 A~C 관문부터 다시 실행합니다.
