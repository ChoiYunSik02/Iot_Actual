## 1. 이 연구가 뭔가

### 한 줄 요약

> 액추에이터의 물리적 한계(물기둥 포화, 제어 지연) 아래에서
> TLCD 제진 성능이 **언제, 왜 무너지는가**를 MATLAB으로 규명한다.

### 주제가 바뀐 경위

1주차에는 **Keenon T10 화재경보 로봇**을 선정했습니다. 그런데 구체화하면서 세 가지 문제가 나왔습니다.

- 액추에이터 3종(구동·조향·조명)을 다루지만 각각이 얕아짐
- 연기 환경 인식률 데이터가 없어 시뮬레이션 검증 범위가 좁음
- 교수님 목표가 학술지 투고인데, 시나리오 재현형은 새 기여를 주장하기 어려움

1주차 발표 마지막 장에 **"구현 상황에 따라 건물 능동제진으로 변경될 수 있다"**고 이미 명시해 뒀고,
건물 능동제진이 1순위 백업안이었으므로 2주차에 정식 전환했습니다.

여기에 교수님이 **"무게추를 물로 채우면 효율도 좋고 재미있다"**고 제안하셔서,
물을 쓰는 감쇠기 중 **TLCD** 방식으로 구체화했습니다.

### 반드시 알아야 할 3가지

**① 질문이 바뀌었습니다.**
"제어하면 좋아지는가"는 이미 답이 나온 질문입니다. 이 팀은 그걸 묻지 않습니다.
**"액추에이터 한계 때문에 언제 무너지는가"**를 묻습니다.
제안이나 코드를 낼 때 이 방향을 벗어나지 마세요.

**② TLCD이지 TLD가 아닙니다.**

| | TLD | **TLCD** |
|---|---|---|
| 형태 | 넓은 물탱크, 수면이 출렁임 | **U자관**, 물이 좌우로 오르내림 |
| 방정식 | 천수방정식 / CFD 필요 | **상미분방정식 1개** |

누가 "출렁이는 물탱크"로 모델링하려 하면 잘못된 방향입니다.

**③ 툴박스를 쓰면 안 됩니다.**

## 2. 핵심 이론

### 지배방정식

```
건물:  (Ms + mf·e·eᵀ)·ẍ  +  α·mf·e·ẍf  +  Cs·ẋ  +  Ks·x  =  −(Ms + mf·e·eᵀ)·r·ag
액체:   α·mf·eᵀ·ẍ  +  mf·ẍf  +  ½ρA·ξ·|ẋf|·ẋf  +  2ρAg·xf  =  −α·mf·ag
        └─ 관성 ─┘   └관성┘   └─ 비선형 감쇠 ─┘   └ 복원력 ┘      └ 가진 ┘
```

- `xf, ẋf, ẍf` : 물기둥의 변위·속도·가속도
- `ρ` 밀도, `A` 단면적, `L` 물기둥 전체 길이, `B` 수평부 길이, `ξ` 손실계수

### 고유진동수

$$\omega = \sqrt{2g / L}, \qquad L = B + 2h$$

**질량도 강성도 들어가지 않습니다.** 수위 `h`만 바꾸면 진동수가 바뀝니다.
→ 펌프가 곧 "주파수 조절 액추에이터"입니다.

### 액추에이터가 2종

| | 조절 대상 | 응답 속도 | 역할 |
|---|---|---|---|
| **펌프** | 수위 h → 진동수 ω | 수십 초 ~ 분 | 지진 **전후** 재튜닝 |
| **밸브** | 손실계수 ξ → 감쇠비 | 밀리초 | 지진 **중** 준능동 제어 |

느린 액추에이터와 빠른 액추에이터가 서로 다른 시간대를 담당합니다.
이게 이 주제를 IoT 액추에이터 과목에 맞다고 판단한 근거입니다.

### 설계 파라미터

| 기호 | 이름 | 범위 | 현재값 |
|---|---|---|---|
| μ | 질량비 | 1~5% | **5%** |
| α | 길이비 B/L | 0.6~0.8 | **0.8** |
| γ | 튜닝비 ωf/ωs | 0.95~1.0 | **0.98** |
| ξ | 손실계수 | 가변 | 밸브로 실시간 조절 |

초기값은 PLOS ONE(2022) 4층 프레임 진동대 실험의 검증된 값입니다.

## 5. 지금까지 나온 결과

### ① 3층 모델은 물리적으로 불가능합니다 ⚠️ 가장 중요

```
1차 진동수 1.200 Hz  →  L = 0.359 m
수직부 높이 h = 0.036 m      ← 스트로크 한계 3.6 cm
단면적    A = 25.6 m²        ← 원형 환산 직경 5.71 m
RMS 저감률 = 0.5%   물기둥 사용률 = 1.27 (포화)
```

**지름 5.7m 관에 물이 3.6cm.** 감쇠기가 아니라 얕은 수영장입니다.

원인: `ω = √(2g/L)`에서 주기를 짧게 하려면 L을 줄여야 하는데,
질량비를 유지하려면 단면적 `A = mf/(ρL)`이 폭발합니다.

장주기 모델(0.5Hz)로 바꾸면 L=2.06m, h=20.6cm, **RMS 저감 33.7%** —
문헌값 23~35%에 정확히 들어옵니다.

**이건 저희 실수가 아닙니다.** Acta Mechanica(2024)와 J. Infrastruct. Preserv.
Resil.(2026)이 "단주기 저층 건물은 TLCD 튜닝이 어렵다"고 같은 지적을 하고 있습니다.

### ② 성능 절벽 — 지진마다 다릅니다

스트로크 한계 20.6cm 조건:

| 지진 | 최대 저감률 | 포화 시작 | 절벽 위치 | 절벽 이후 |
|---|---|---|---|---|
| 경주형 (0.1초) | 40.8% | 0.375g | 0.50g | 32.1% |
| **포항형 (0.5~0.6초)** | **44.0%** | **0.075g** | **0.15g** | **7.8%** |
| El Centro형 (0.5초) | 44.2% | 0.075g | 0.20g | 26.5% |

**포항형이 압도적으로 취약합니다.** 주기가 건물과 겹쳐 공진하기 때문입니다.
경주형은 반대로 주파수가 어긋나 물이 덜 움직이고, 덕분에 포화는 늦지만 효과도 제한적입니다.

→ 2주차에 세운 가설(**"잘 듣는 조건이 곧 위험한 조건"**)이 검증되었습니다.

### ③ 제어 지연은 예상보다 영향이 작습니다

| 지연 | RMS 저감률 |
|---|---|
| 0 ms | 39.6% |
| 100 ms | 37.0% |
| 200 ms | 37.4% |

**발산이 일어나지 않습니다.** 200ms에서도 저하가 2.6%p뿐입니다.
"준능동 시스템은 본질적으로 안정하다"는 문헌 견해와 일치합니다.

대신 다른 게 나왔습니다 — **경주형에서 현재 on-off 제어 법칙이
고정 오리피스보다 7.2%p 나쁩니다.** 고주파에 이 법칙이 안 맞습니다.

→ 연구축 ②의 질문을 "지연 임계값"에서 **"제어 법칙의 지진별 적합성"**으로
바꾸자고 3주차 발표에서 제안했습니다.

## 6. Claude Code 플러그인 (`iot-tlcd/`)

주간보고서를 1주차 디자인 시스템 그대로 자동 생성하는 도구입니다.
Claude Code를 쓴다면 설치하세요. 안 쓴다면 무시해도 됩니다.

### 설치

`iot-tlcd` 폴더를 통째로 복사:

```
Windows :  C:\Users\<사용자명>\.claude\skills\iot-tlcd
macOS   :  ~/.claude/skills/iot-tlcd
```

Claude Code 재시작 → `iot-tlcd@skills-dir`로 자동 로드됩니다.

### 설치하면

```
4주차 주간보고서 만들어줘. 발표 15분이야.
TLCD 운동방정식 설명해줘
지금 몇 주차고 뭘 해야 하지?
```

연구 배경·방정식·선행연구·일정을 이미 알고 있는 상태에서 시작합니다.
매번 배경 설명할 필요가 없어집니다.

자세한 내용은 `iot-tlcd/README.md` 참조.

## 7. 결정 대기 중인 사항

3주차 발표에서 교수님께 여쭐 두 가지입니다.

### ① 건물 층수

| 안 | 방향 | 평가 |
|---|---|---|
| 1안 | 6~10층으로 상향 | 안전하지만 "국내 저층" 명분 약화 |
| 2안 | 3층 유지, 한계를 결과로 | "안 된다"로 끝나면 기여 빈약 |
| **3안** | **문제 제시 + 해법 검증** | **팀 권장** — 3층 결과가 그대로 쓰임 |

3안은 슬라이딩 TLCD(Acta Mechanica 2024 방식) 추가 구현이 필요합니다. 약 2주 예상.

### ② 연구축 ②의 질문 재설정

"지연 임계값" → "제어 법칙의 지진별 적합성"으로 옮길지.

## 10. 주의사항

- **지진파는 합성입니다.** `gen_ground.m`이 만드는 건 Kanai-Tajimi 필터로
  지배 주기와 지속시간만 재현한 대체파입니다. 논문·최종보고서에는 쓸 수 없습니다.
- **툴박스 함수 금지.** 새 코드를 짤 때도 `tf`, `lsim`, `rms` 등을 쓰지 마세요.
- **애니메이션은 실제 비율이 아닙니다.** 변위 15배 확대, U자관도 확대해서 그렸습니다.
  화면에 표기돼 있으니 발표 때 그대로 설명하면 됩니다.
- **PPT 디자인을 바꾸지 마세요.** 색·좌표는 1주차 원본에서 추출한 값이라,
  바꾸면 주차별 자료의 일관성이 깨집니다.
